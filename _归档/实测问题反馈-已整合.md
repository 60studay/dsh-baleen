## 🔴 P0：控制权切到 human 后，串口仍被占用（已复现）

### 现象

用户把控制权交给「人类接管」，期望释放串口给自己用串口助手，但：

```
control = human          ← 状态已切到 human
COM10 打不开             ← 串口仍被网页进程占用
PermissionError(13, '拒绝访问')
```

### 复现步骤

1. 启动网页版：`python bridge.py web --scene 蓝牙AT --port 8898`
2. 网页点「人类接管」
3. 用外部程序（或 pyserial）尝试打开 COM10
4. **结果：PermissionError，打不开**

### 用户期望

> "操控权交给用户的时候，就不应该被你占用了吧？"

**控制权 = 谁有权发命令，串口占用 = 谁持有句柄。这两者应该解耦：**

| 控制权 | 期望的串口行为 |
|---|---|
| `ai` | 网页持有串口（AI 通过网页发命令） |
| `human` | **网页应释放串口**，让用户用自己的串口助手 |
| `paused` | **网页应释放串口** |

### 建议实现

```python
def on_control_change(new_state):
    if new_state in ("human", "paused"):
        release_port()          # 关闭串口句柄，允许外部程序使用
    elif new_state == "ai":
        acquire_port()          # 重新打开串口
```

**注意**：释放后如果用户想再让 AI 发命令，需要先切回 `ai`（此时重新获取串口）。

### 附带问题：`/control` 接口返回 400

用 `POST /control {"action": "human"}` 调用时返回 `400 Bad Request`，
但网页上点按钮是好的——说明前端可能有额外字段或 header。
**建议**：明确 `/control` 的请求格式，或让 400 时返回具体原因。

## 🟡 P1：网页无法编辑异常判定规则

### 现象

网页上「异常判定」只有开关和来源选择，规则本身必须手动改 `config.json`：

```
异常判定  [开启]
判定来源  [轮询 ▼]
—— 未启用
规则与白名单在场景 config.json 的 watch 块里配置；判定出错不会影响收发。
```

用户反馈：**"我发现异常，判定没有给我写处理问题的地方"**

### 用户期望

网页上能直接**增删改规则**，不用碰 JSON。

### 建议 UI

```
┌─────────────────────────────┐
│ 异常判定  [开启]            │
│ 判定来源 [轮询 ▼]           │
│ ─────────────────────────── │
│ 规则列表                    │
│ ☑ 规则1  含"X" → 发"Y"      │
│ ☑ 规则2  无响应 → 发"Z"     │
│ [+ 添加规则]                │
└─────────────────────────────┘
```

点「添加规则」弹窗：

```
名称   [___________]
当     [包含 ▼] [___________]
则     [发送 ▼] [___________]
重试   [3] 次
       [保存] [取消]
```

**保存后写回场景的 `config.json`。**

## 🟡 P1：「退出」和「释放串口」应该分开

### 现象

现在只有一个「退出并释放串口」按钮，点了之后：

```javascript
if (!confirm('退出并释放串口？退出后网页将无法访问。')) return;
```

**HTTP 服务整个停掉，网页再也打不开**，必须回终端重新启动。

### 问题

用户想「临时让串口给别的程序用」，但不想丢掉网页界面。

### 建议：拆成两个按钮

| 按钮 | 网页 | 串口 | 场景 |
|---|---|---|---|
| **暂停并释放串口** | ✅ 仍可访问 | ❌ 释放 | 想临时用串口助手 |
| **彻底退出** | ❌ 关闭 | ❌ 释放 | 真正不用了 |

## 🟡 P2：串口被占用时提示不明确

### 现象

串口被占用时，只报 `PermissionError` 或笼统的"被占用"，
用户不知道**是谁占的**。

### 建议

状态栏明确显示：

```
COM10  [被本网页占用]      ← 网页自己占的
COM10  [被其他程序占用]    ← 外部程序占的
COM10  [可用]              ← 空闲
```

并附提示：

```
串口被占用。可能原因：
- 本网页的监视模式正在运行
- 串口助手 V1.1 等外部程序
- 其他终端工具
```

## 补充说明：为什么 P0 最重要

用户的核心使用场景是：

```
调参时：用串口助手 V1.1（他自己熟悉的工具）
调试时：用 AI（通过插件）
```

如果「人类接管」不释放串口，用户**每次想用串口助手都得先关网页**，
那就失去了"网页 + AI + 串口助手共存"的意义。

**这条不修，整个"人机协同"的价值大打折扣。**
