给 DSH 装上串口能力：**装一次，之后每个新会话都能直接收发串口**。
这是一个**通用串口工具**，不认识任何特定设备——设备知识全在 `protocols/<场景>/` 里。

## 7 个工具

| 工具 | 作用 |
|---|---|
| `serial_list` | 列出串口（含 VID:PID）+ 每个场景**现在**会落到哪个口 |
| `serial_send` | 发一条命令，返回回显（文字 + hex），端口每次自动重新匹配 |
| `serial_read` | 回看该场景最近的收发日志 |
| `serial_info` | 场景参数、匹配规则、watch 配置、完整协议档案 |
| `serial_status` | 控制权、AI 现在能不能发、最近告警 |
| `serial_watch` | 读/改两个独立的监视开关（无需开网页） |
| `serial_control` | 交接控制权（无需开网页） |

**设计原则：不常驻、不占口。** 每次调用临时打开串口 → 收发 → 立刻关闭，
不会和串口助手抢 COM 口。

## v2 新增能力

### 1. 串口自动匹配（不再怕换口）

场景配置里按优先级匹配，**永远先扫描**：

```json
{
  "com": "COM7",                // 首选：精确号（可能过期）
  "match": "CH340",             // 次选：描述模糊匹配（不区分大小写）
  "match_vid_pid": "1A86:7523"  // 最精确：VID:PID
}
```

顺序：`match_vid_pid` → `match` → `com`。匹配到多个会列出候选让你选。
**自动纠正**：配置写 COM7、实际在 COM10，会直接用 COM10 并在返回值里注明。

> 实测：写这份文档期间设备正好从 COM7 换到了 COM10，插件自动跟上了。

### 2. 三类故障分开报

| 情况 | 你会看到 |
|---|---|
| 设备没插 | `没找到匹配的串口设备` + 请检查 USB/驱动 + 当前可用串口清单 |
| 口被占用 | `COM10 被其他程序占用` + 提示关掉串口助手/监视模式 |
| 设备不回 | `已连接 COM10，但设备无响应` + 提示查波特率/供电/TX-RX |

Python 堆栈永远不会出现在你面前。

### 3. 网页版不长期占口 + 退出按钮

```bash
python bridge.py web --scene <场景>            # 默认轻模式，不占口
python bridge.py web --scene <场景> --mode watch   # 监视模式，占口但能看连续流
```

| 能力 | 轻模式（默认） | 监视模式 |
|---|---|---|
| 发命令看回复 | ✅ | ✅ |
| 与 AI 的 `serial_send` 共存 | ✅ | ❌（会占口） |
| 与你的串口助手共存 | ✅ | ❌ |
| 看连续数据流 / 主动上报 | ❌ 会漏（可点「读一次」临时读一帧） | ✅ |

轻模式下网页**不会主动读串口**：`/poll` 直接返回跳过，只有你点「读一次」才临时开口。
这样网页开着的时候，串口助手和 AI 都不会被挤开。

右上角 **[彻底退出]** 会停服务并立即放开 COM 口；
只想临时把口让给别人，用侧栏的 **[暂停并释放串口]**（网页还留着）。

网页还有：串口下拉框、波特率下拉框、**[AI 自动选择]**、文字/十六进制切换、
连接模式切换、两个监视开关、四键控制权、可滚动的**状态轨道**。

### 4. 控制权状态机

```
human ──[交给AI]──→ ai ──[暂停AI]──→ paused
  ↑                  │                 │
  └───[人类接管]──────┴───[继续AI]─────┘
```

- 状态存在共享文件里，网页和插件进程看到的是同一份
- **人类命令永远优先**：AI 托管时你发任何命令，立即拉回 `human`
- 按钮合法性严格按文档的按钮表（12 种组合都已实测）
- **重复点同一个按钮是幂等的**（返回 200 + "已经在目标状态"），不会报 400

#### 门禁：只有 `ai` 才允许 AI 发命令

`serial_send` 执行前必查控制权，**`human` / `paused` 一律拒绝**，并给出可操作的下一步：

| 控制权 | AI 能否发 | 被拒绝时提示你去做什么 |
|---|---|---|
| `ai` | ✅ | — |
| `human` | ❌ | 在网页点[交给AI]，或 `serial_control action=ai` |
| `paused` | ❌ | 在网页点[继续AI]，或 `serial_control action=resume` |

早期版本做过"没人开网页就放行"的宽松门禁，实测表明这会让控制权形同虚设
（切到 human 后 AI 照样能发），**已取消**。现在无论有没有开网页，规则都一样。

要单人使用，直接把控制权设成 `ai` 即可——网页、`serial_control`、
命令行 `bridge.py control` 三条路都能改。

### 5. 定时询问：两个**完全独立**的开关

这是 v2 的核心设计。轮询和判定拆开，任一出错都不牵连另一个：

```json
{
  "watch": {
    "send_enabled": false,          // 开关1：是否定时发 command
    "command": "P",
    "interval_ms": 1000,

    "check_enabled": false,         // 开关2：是否对收到的数据跑 rules
    "check_source": "watch_only",   // watch_only / manual_only / both
    "rules": [ ... ],
    "allowed_auto_commands": ["R", "X"]
  }
}
```

| send | check | 效果 |
|---|---|---|
| ❌ | ❌ | 纯手动串口助手 |
| ✅ | ❌ | 定时发，自己看回显 |
| ❌ | ✅ | 手动操作 + 自动查异常 |
| ✅ | ✅ | 全自动监控 |

#### 四种通用判据（没有第五种）

| type | 参数 | 含义 |
|---|---|---|
| `contains` | `value` | 回显包含某字符串 |
| `equals` | `value` | 回显完全等于某值 |
| `regex` | `pattern`（可选 `condition`） | 正则匹配 |
| `no_response` | `consecutive` | 连续 N 次无回显 |

#### 隔离（防止规则拖垮收发）

- 判定跑在**常驻子进程**里；卡住就 kill 并重启，收发线程不受影响
- 非法正则只记日志，其它规则照常
- 同一规则有冷却期，防止触发风暴
- 连续 N 次判定失败 → 熔断停判定，串口照常收发
- 自动命令受 `allowed_auto_commands` 白名单限制，**白名单为空则禁止一切自动命令**

> ⚠️ 别把运动类命令加进白名单。
>
> 关于"超时保护"的一个重要实现说明：第一版用线程 + `join(timeout)`，
> 实测**会卡死**——CPython 的 `re` 在灾难性回溯期间持有 GIL，主线程连切换都做不到。
> 所以改成常驻子进程，超时直接 `kill()`。

### 6. 告警怎么通知你

DSH 是回合制，**AI 无法被主动唤醒**。所以：

```
异常发生 → 写 alerts.jsonl → 网页顶部红条 → 你决定是否叫 AI
                                        → 或 AI 下次被唤起时自己读 serial_status
```

不会承诺"AI 自动弹消息"。

## 场景 = 一个硬件

`protocols\<场景名>\` 一个目录一个场景，已带两个：

| 场景 | 内容 |
|---|---|
| `蓝牙AT` | HC-05 + 底盘命令集（含全部实测记录与踩坑） |
| `文字游戏` | 暗号表模板 |
| `Modbus从站` | 通用性验证用例：9600 8N1、无换行、hex 命令、正则判据 |

新增硬件 = 新建目录，**不用改代码**。判断标准只有一句：

> 换一台完全不同的串口设备，我需要改代码吗？要改 → 设计错了。

1. DSH → **Plugins** → **Add plugin**

3. **Install** → **Enable now**
4. 开新会话，说"列一下串口"

## 配置

插件级（`cordis.patch.yml`，Plugins 页可改）：

| 键 | 说明 |
|---|---|
| `pythonPath` | 跑内核的解释器。默认 DSH 自带；找不到会自动退到 `python` / `py -3` |
| `logRoot` | 日志根目录，默认 `<你的日志目录>` |
| `protocolRoot` | 可选：把场景目录指到插件外面 |

场景级（`protocols/<场景>/config.json`）：

| 键 | 默认 | 说明 |
|---|---|---|
| `com` / `match` / `match_vid_pid` | — | 见上文匹配规则 |
| `baud` | 115200 | 波特率 |
| `newline` | `\r\n` | 每条命令自动补的结尾 |
| `wait_first_byte_ms` | 1500 | 等首字节上限（设备慢就调大） |
| `quiet_ms` | 200 | 线路安静多久算收完 |
| `watch.*` | 见上文 | 两个开关 + 规则 + 白名单 |

**不用给 Python 装 pyserial**：插件自带（`vendor/pyserial-3.5`，BSD），
通过 `PYTHONPATH` 注入，不污染目标解释器。

## v2.1 修复（实测反馈）

### 控制权与串口占用已解耦（P0）

以前「人类接管」只改了状态，串口还攥在网页手里——你想开串口助手，得先关网页。
现在**控制权决定谁有权发命令，占用决定谁持有句柄**，两者分开：

| 控制权 | 串口句柄 |
|---|---|
| `ai` | 网页打开并持有（watch 模式） |
| `human` | **立刻关闭句柄**，串口助手可以打开 |
| `paused` | **立刻关闭句柄** |

#### 释放动作挂在"状态变化"上，不是挂在按钮上

这一点很关键。控制权存在共享文件里，改它的路径有三条：

1. 网页按钮 `POST /control`
2. `serial_control` 工具（走 CLI 子进程）
3. 你在终端跑 `bridge.py control`

如果释放动作只写在网页按钮里，第 2、3 条改完状态后**网页根本不知道**，
仍然攥着串口——这正是实测反馈里遇到的坑。

所以现在串口占用由一个看门狗每秒对齐一次控制权（`reconcile_port`），
三条路径改的状态都会被收敛。实测：CLI 把状态改成 human 后，
**1 秒内**串口就被释放，外部程序随即能打开。

#### 轻模式轮询也让开

轻模式下网页每 700ms 轮询一次 `/poll`，每次都要临时开口。
human 状态下这个轮询直接返回 `skipped`，**一次都不碰串口**。

实测：human 状态下让外部程序连续占用 12 秒（每 0.5 秒开关一次），
24 次打开全部成功，0 次被网页抢走。

### 暂停 ≠ 退出

| 按钮 | 网页 | 串口 |
|---|---|---|
| **暂停并释放串口** | 仍可访问 | 释放 |
| **彻底退出** | 关闭 | 释放 |

只想临时把口让给串口助手，点第一个就够了，不用重开网页。

### 网页可直接编辑规则

侧栏能增删改规则（名称 / 判据 / 自动命令 / 重试次数），保存时写回场景
`config.json`（保留文件里其它键），写盘前会校验：非法正则、未知判据、
缺字段都会被拒绝并说明原因。

### 占用者一目了然

状态栏显示 `可用` / `被本网页占用` / `被其他程序占用`，带具体说明。

### `/control` 的 400 会说清楚缺什么

`{"action": ...}` 缺字段时返回明确的 `config` 错误和请求体示例，而不是空白 400。

## 自测

```bash
python selfcheck_rules.py          # 32 项：四种判据 / 非法正则 / 超时 / 白名单 / 限流 / 熔断 / 通用性
python selfcheck_port_hold.py      # 16 项：控制权↔串口句柄 的解耦
python selfcheck_control_gate.py   # 34 项：AI 门禁 + /control 幂等与按钮矩阵
python selfcheck_autosend.py       # 14 项：定时发送 + 轻模式不占口（假设备，无需硬件）
python selfcheck_hex.py            # 11 项：十六进制按原始字节发送（假回环，无需硬件）
python selfcheck_watch.py          # 15 项：双开关独立性 / check_source / 规则出错不影响收发（需要硬件）
```

前五个不需要串口，拔掉设备也能跑；`selfcheck_watch.py` 找不到设备时会打印 SKIP 并以 0 退出。

## 已知限制

- 轻模式默认不读串口，所以设备主动上报的数据**会漏**——要看连续流请切监视模式，
  或点「读一次」临时读一帧。
- 网页和控制权状态按**场景**隔离；不同场景之间互不影响。
- 监视模式占口期间，AI 的 `serial_send` 会报"被占用"，这是预期行为。
- 同一场景同时只允许一个网页实例（启动时会探测，已有实例则直接退出）。
- 单次工具调用超时 25 秒。
