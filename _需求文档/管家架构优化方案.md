# 串口管家架构优化方案

> 编写日期：2026-11-05
> 针对版本：`<插件目录>\`（当前版本）
> 前置：先完成 `Bug修复清单.md` 里的 Bug 7、Bug 8

---

## ⚠️ 本文档要解决的核心问题

### 用户的原话

> "我假如不主动去看可视化界面，把任务交给你，你就只能按慢着来吗？"

### 问题本质

**速度取决于"谁持有串口"，而不是"谁在用"——这是耦合错误。**

```
网页开着 → 管家在跑 → AI 走管家 → 快（事件驱动，~0 延迟）
网页关了 → 管家没了 → AI 自己开串口 → 慢（等 quiet_ms 600ms）
```

用户把任务交给 AI 时**根本不需要网页**，却被强制慢 0.4 秒/条。

### 现状的两种模式对比

| 模式 | 谁在用 | 串口持有 | 单条命令耗时 |
|---|---|---|---|
| 串口助手（C# WinForms） | 人 | 常驻独占 | ~0（事件驱动） |
| 插件现状 | AI | 临时开关 | **~1.2 秒** |

**为什么串口助手快**：它用 `SerialPort.DataReceived` 事件，串口一直开着，有数据立刻回调。

**为什么插件慢**：每次临时开串口 → 发 → **等 quiet_ms 判断回显结束** → 关。这个"等"就是延迟来源。

## 一、目标架构：管家与网页解耦

### 核心思想

**管家是独立进程，网页只是它的一个客户端。**

```
┌──────────────────────────────────────────┐
│  串口管家（独立进程，事件驱动）            │
│   · 常驻持有串口                          │
│   · 收到数据立即广播给所有订阅者           │
│   · 提供 /send 接口                       │
└──────────┬───────────────────────────────┘
           │
     ┌─────┴──────┬──────────┐
     ↓            ↓          ↓
  网页 UI      AI 插件    其他客户端
 （可选）    （按需连接）  （可选）
```

### 三种运行状态

| 状态 | 谁在跑 | AI 速度 | 网页 | 串口助手 |
|---|---|---|---|---|
| **A. 无管家**（默认） | 只有插件 | 慢（1.2s/条） | 可选 | ✅ 可用 |
| **B. 管家 + 网页** | 管家 + 网页 | **快（~0）** | ✅ 可视化 | ❌ 占用 |
| **C. 只有管家** | 管家（无网页） | **快（~0）** | ❌ 不开 | ❌ 占用 |

**关键**：B 和 C 里 AI 都是快的，**不依赖网页是否打开**。

## 二、AI 自主启停管家（核心能力）

### 需求

**AI 自己判断该不该开管家，用户什么都不用管。**

### 决策逻辑

```
AI 要发命令
    ↓
检测管家是否在跑
    ├── 在跑 → 走管家接口（快）
    └── 没跑 → 按任务规模判断：
         ├── 单条 / 少量（≤3 条）→ 临时开关（慢，但不占口）
         └── 批量（>3 条）/ 需要抓异步故障 → **主动启动管家**
```

### 实现要求

#### 新增工具 `serial_daemon`

```json
// 启动
serial_daemon({"action": "start", "scene": "蓝牙AT"})
→ {"ok": true, "pid": 12345, "port": "COM10", "mode": "event"}

// 停止
serial_daemon({"action": "stop"})
→ {"ok": true}

// 查询
serial_daemon({"action": "status"})
→ {"running": true, "pid": 12345, "clients": 1, "uptime_s": 120}
```

#### 关键要求

| 要求 | 说明 |
|---|---|
| **幂等** | 已开着就返回现有信息，不要重复启动 |
| **告知用户** | 启动时返回提示："管家已启动，占用 COM10，期间串口助手不可用" |
| **自动超时** | 空闲 N 分钟（默认 10）自动退出释放串口 |
| **优雅退出** | 收到 stop 或超时，先停线程再关串口 |

### 用户知情权

**AI 启动管家时必须告诉用户**：

```
"我要发 10 条命令，启动管家会快很多，但期间你的串口助手打不开 COM10。
 大约 30 秒后自动释放。可以吗？"
```

**或者**：默认自动启动，但**网页/对话里显示状态**：

```
[串口管家运行中 · 占用 COM10 · 空闲 10 分钟后自动释放]
```

## 三、技术实现要点

### 3.1 事件驱动读取

**参考用户现有串口助手的做法**（C# WinForms，`D:\STM32 project\...\串口助手-工程源码`）：

```csharp
serialPort.DataReceived += serialPort_DataReceived;

private void serialPort_DataReceived(object sender, SerialDataReceivedEventArgs e)
{
    int count = serialPort.BytesToRead;
    byte[] dataReceive = new byte[count];
    serialPort.Read(dataReceive, 0, count);
    // 立即显示
}
```

**Python 等价实现**（pyserial）：

```python
class Daemon:
    def __init__(self, port, baud):
        self.ser = serial.Serial(port, baud, timeout=0.05)
        self.thread = threading.Thread(target=self._read_loop, daemon=True)
        self.subscribers = []   # 订阅者列表（网页、AI）
        self.thread.start()
    
    def _read_loop(self):
        while self.running:
            n = self.ser.in_waiting
            if n:
                data = self.ser.read(n)
                self._broadcast(data)      # 立刻广播，零延迟
            else:
                time.sleep(0.005)          # 5ms 轮询，接近实时
```

**关键**：`in_waiting` 有数据就立刻读走并广播，**不等安静**。

### 3.2 数据广播机制

**三种客户端接入方式**：

| 客户端 | 接入方式 | 说明 |
|---|---|---|
| 网页 | HTTP 轮询 `/poll` 或 SSE | 简单，兼容现有实现 |
| AI 插件 | 本地 socket / 文件 / HTTP | 推荐 HTTP，简单 |
| 其他程序 | 可选 | 暂不支持 |

**推荐**：管家起一个本地 HTTP 服务（端口可配，如 8899），提供：

```
POST /send       发命令
GET  /poll       取增量数据（带游标）
GET  /status     查状态
POST /shutdown   退出
```

### 3.3 串口占用与让位

**问题**：管家占着串口，用户想用串口助手怎么办？

**方案**：

| 方案 | 说明 |
|---|---|
| **自动超时**（推荐） | 空闲 10 分钟自动退出 |
| **一键释放** | 桌面快捷方式 / 网页按钮 / AI 工具 |
| **检测让位**（进阶） | 检测到串口被抢，主动退出 |

**检测让位实现**：

```python
def _check_yield(self):
    """定期检查：串口是否被别的程序抢了"""
    try:
        # 尝试再打开一次，如果失败说明被抢
        test = serial.Serial(self.port, timeout=0.1)
        test.close()
    except serial.SerialException:
        self.stop()   # 被抢了，主动退出
```

### 3.4 与现有代码的兼容

**必须保持**：

| 现有能力 | 要求 |
|---|---|
| `serial_send` 单条发送 | 保留，无管家时用临时开关 |
| `serial_list` / `serial_read` / `serial_info` | 完全不变 |
| `serial_status` | 增加 `daemon_running` 字段 |
| 网页 `--web` 模式 | 保留，作为管家的一个客户端 |

**改动点**：

```
serial_send 内部逻辑：
    if daemon_running:
        走 daemon 的 /send 接口
    else:
        临时开关（现有逻辑）
```

## 七、验收标准

### 基础功能

- [ ] 管家启动后，串口被占用（外部程序打不开）
- [ ] 管家关闭后，串口释放
- [ ] 管家运行时，AI 发命令延迟 < 100ms
- [ ] 管家运行时，网页能实时看到数据

### 解耦验证（核心）

- [ ] **不开网页，AI 也能启动管家**
- [ ] **不开网页，AI 发命令仍然快**
- [ ] 网页只是客户端，开关不影响管家

### 自主决策

- [ ] AI 发少量命令（≤3）时，不启动管家（不占口）
- [ ] AI 发批量命令时，自动启动管家
- [ ] 启动时告知用户（返回提示或状态显示）

### 让位机制

- [ ] 空闲超时后自动释放
- [ ] 用户可以手动停止
- [ ] 串口被抢时能检测并退出

### 兼容性

- [ ] 无管家时，`serial_send` 仍能工作（降级到临时开关）
- [ ] 现有所有工具行为不变
- [ ] 现有网页功能不变

## 八、给开发者的话

### 这个改动的本质

**把"串口持有"从网页里拆出来，变成独立的基础设施。**

现在的错误耦合：

```
网页 → 持有串口 → AI 依赖网页 → 不开网页就慢
```

目标：

```
管家 → 持有串口 → 网页和 AI 都是客户端 → 谁开谁关都不影响对方
```

### 三条铁律仍然适用

1. **通用性**：管家不认识任何设备，只做字节转发
2. **不阻塞**：广播/日志/判定都不能卡住读取循环
3. **控制权**：管家也要遵守 human/paused/ai 状态机

### 最容易出错的地方

| 坑 | 后果 | 防范 |
|---|---|---|
| 管家启动时没检查已存在实例 | 两个管家抢串口 | 启动前检查 PID 文件 |
| 广播阻塞 | 一个慢客户端拖垮全部 | 每个客户端独立队列 |
| 超时后没真正关串口 | 句柄泄漏 | try/finally 保证 close |
| 忘记通知用户 | 用户发现串口助手打不开，困惑 | 启动时返回明确提示 |

## 九、可选：更轻的替代方案

**如果觉得管家太重，可以先做这个**：

### 方案：AI 长连接模式

```
AI 要发多条命令时：
    serial_batch_session({
        "scene": "蓝牙AT",
        "commands": ["A", "W 500 500 500 500", "P"],
        "keep_open_ms": 5000    // 5 秒内保持串口打开
    })
```

**原理**：一次调用内，串口开着发完所有命令，**只等一次安静**而不是每条都等。

| 优点 | 缺点 |
|---|---|
| 工作量小（0.5 天） | 只解决批量场景，单条仍慢 |
| 不占口（用完就关） | 无法实时监听 |

**适合**：AI 执行"发一批命令"的任务，不需要持续监听。

## 十、总结

| 问题 | 现状 | 目标 |
|---|---|---|
| AI 速度依赖网页 | ❌ 不开网页就慢 | ✅ 管家独立，AI 自主启停 |
| AI 发的网页看不到 | ❌ 两条独立路径 | ✅ 统一走管家 |
| 串口被永久占用 | ⚠️ 需手动关 | ✅ 超时自动释放 |
| 单条命令 1.2 秒 | ⚠️ 慢 | ✅ 管家模式 ~0 |

**核心一句话**：

> **管家是独立基础设施，网页和 AI 都是它的客户端。谁开谁关，互不影响。**
