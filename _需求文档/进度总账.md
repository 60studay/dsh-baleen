## 四点九九、🔴 未修的 bug（已报实现方 23:58）

**`port_manager.owner()` 在轻模式下每 5 秒真的打开一次串口。**

证据：占住 COM10 后，`/status` 第 5 秒从 `owner=free` 翻成 `owner=other`——缓存一过期就真 open 了。

三个后果：每 5 秒一次 DTR/RTS 脉冲（可能复位板子）；间歇挡住别的程序；跨进程时自己撞自己（拿 `port_busy` 而"其他程序"就是鲸歌自己）。

**建议**：轻模式不探测，改成显式入口；至少把 5 秒缓存延到 30~60 秒。

**已验证端到端**（插件 → Python → COM7 → 板子）：
```
P -> OK PONG        V -> OK VER stc8g-lab v1
K -> OK KEY 1       E 中文测试 12345 -> OK ECHO 中文测试 12345

```

**v4 固件（2026-11-07 11:40）**：真正修掉自发刷屏（v3 只堵了一半）。根因是环形缓冲只有写指针，无法区分回绕；v4 改成「取走就清零」。**已验证：网页轮询下 14 秒静默、20 次 P 零失败。**

**v3**：去掉 printf（RAM 溢出），修了 v2 的自发刷屏的一半（`printf` 吃光 128 字节内部 RAM + 环形缓冲回绕重放旧字节），`data` 从 101 降到 84 字节。命令和 v2 一致，`V` 回 `v3`。

**v2 加了故障注入**，这是最有价值的部分：
`D <ms>` 拖慢 / `N <n>` 截断回复 / `J <n>` 塞垃圾 / `S <n>` 长突发 / `B` 二进制帧。
**验证过它能逼出插件的错误路径**：`D 500` 超过场景的 `wait_first_byte_ms=300`，
插件正确报 `no_response`，并带出了场景专属提示（`no_response_hint`）。

**三个坑（都已写进注释/代码）**：
- **`0 Error(s)` 不代表没问题**：`STC8G_H_Delay.c` 的 `delay_ms()` 定义被注释掉了，
  只有声明。链接器报 `WARNING L1: UNRESOLVED EXTERNAL` 但照样生成 hex，
  运行到就跳地址 0 = **MCU 莫名复位**。`flash.py` 已加硬检查（有未解析符号就拒绝烧录，实测有效）。
- **Keil 增量编译会复用旧 `.obj`**：改回正确代码后它发现 `.obj` 比 `.c` 新，跳过编译，
  把上一轮的未解析符号又链进去。已改用 `-r` 全量重编。
- **C51 保留字**：`data` 和 `bit` 是 8051 的内存类型/位类型关键字，**不能当变量名**。

**两个坑（已写进 flash.py 注释）**：
1. **不能加 `-t`**：`-t 11059200` 会让 stcgal 请求精确微调，STC8G1K08A 步进落不到这个值 →
   `Protocol error: frequency trimming unsuccessful`。芯片当前 11.054MHz，误差 0.05%，别动。
2. **CH340 与 MCU 共用 USB 时**，冷启动会把 CH340 一起断掉，句柄失效（`WriteFile failed`）。
   `flash.py` 已加 3 次自动重试。
