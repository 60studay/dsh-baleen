## 四点九九、🔴 未修的 bug（已报实现方 23:58）

**`port_manager.owner()` 在轻模式下每 5 秒真的打开一次串口。**

证据：占住 COM10 后，`/status` 第 5 秒从 `owner=free` 翻成 `owner=other`——缓存一过期就真 open 了。

三个后果：每 5 秒一次 DTR/RTS 脉冲（可能复位板子）；间歇挡住别的程序；跨进程时自己撞自己（拿 `port_busy` 而"其他程序"就是鲸歌自己）。

**建议**：轻模式不探测，改成显式入口；至少把 5 秒缓存延到 30~60 秒。

### 🔴 另一个未修 bug：`serial_status` 每次都失败（2026-11-07 00:40 发现）

真机调用直接报错：

```
tool "serial_status" returned invalid output:
"value.transport" is not a declared property (additionalProperties: false)
```

**根因**：`index.js` 的 `execute` 返回了 `transport`，但 `output.schema`
（`additionalProperties: false`）里没声明它。`87515bb` 抽 Transport 层时加的返回字段，漏了 schema。

**影响**：`serial_status` 是"动手前先查控制权"的工具，坏了等于 AI 瞎发命令。

**修法**：schema 里补
```js
transport: { type: ['object','null'], additionalProperties: true }
```
（用 `additionalProperties: true` 是因为 `describe_transport()` 的字段随传输类型变，
逐字段写死会导致下次加传输方式又崩一次。）

**已由 `selfcheck_tools.py` 覆盖** —— 修好后这一项会转绿。

4. **保持跨平台** —— 不许出现 `C:\\`、`if platform`、`sys.platform ==`
